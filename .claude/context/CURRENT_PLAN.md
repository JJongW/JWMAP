## 목표
oomap.kr(project/)를 기능 추가 없이 다듬어, 사용자가 운영자의 믿을 만한 추천을 이해하고 오늘 갈 곳을 빠르게 고르게 한다.

## 레포 범위
project/ (사용자 웹). admin·odiga-api·DB 데이터는 건드리지 않음. 배포 안 함.

## 근본 원인 (코드 + 1280×649 실제 화면으로 확인)
1. 볼거리 조건 불일치: 질문 화면은 볼거리용 라벨(가볍게·실내 위주)을 쓰지만 같은 값(lunch·wait_short)을 결과 칩·엔진은 맛집 라벨(점심·줄 안 서는 곳)과 맛집 태그 키워드(웨이팅 적음)로 처리 → 라벨이 바뀌고 볼거리 태그와 안 맞아 결과 0.
   식후 카페는 우선 조건을 못 지키면 조건을 몰래 빼고 골랐음.
2. 추천 강도 배지가 방문 여부와 무관: 미방문 511곳 중 105곳이 L3 '검증됨'. 헤더는 "제가 직접 다녀온 곳"이라고 약속. curator_visited 값이 비면 방문으로 간주.
3. 첫 화면: 브랜드 헤더·자연어 입력·이름 검색·칩 3줄·그라데이션 카드(지역 칩)·검은 하단 CTA가 같은 무게 → 649px 높이에서 목록 1곳만 보임.
4. 추천 이유: 운영자 한 줄이 없으면 "점심에 둘이 가기 좋은 … 후보예요" 같은 문장을 지어냄, 보조 후보 설명에 주차·예약·평점, 목록에 '믿고 후보에 넣기 좋은 곳 · #태그'.
5. 결과 화면 하단 바가 fixed라 첫 카드(222~792px)를 562px부터 가림. '3곳만 추려보기' 결과는 1순위+대안 2+식후 카페 = 최대 4곳.
