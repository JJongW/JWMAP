# OOMAP 카드뉴스 제작 규칙

카드뉴스를 자동으로 만들 때 이 규칙을 따른다. 사람이 검수할 때도 같은 기준으로 본다.
근거: 용산 카페 5곳 시험 제작(2026-11-04)과 `INSTAGRAM_TIPS.md`에 정리한 인스타 운영 팁.

## 제작 현황 (중복 방지)

- Figma 「제작 현황」 페이지(보드 27:27)에 카드뉴스로 쓸 수 있는 장소가 지역별로 있다. 줄 이름은 place_id다.
- **단일**은 이 장소 하나만 소개한 게시물(Template 1)을 올렸는지(체크), **묶음(회)**은 여러 곳을 묶은 게시물(Template 2)에 들어간 횟수(숫자)다. 한 장소가 여러 묶음에 들어갈 수 있다. 사용자가 게시 후 고친다.
- 기획할 때 `admin/scripts/card-checklist-read.mjs --unused single|multi`로 아직 안 쓴 장소를 고른다. 묶음 횟수가 적은 장소가 앞에 온다.
- 토큰은 `project/.env`의 `FIGMA_READ_TOKEN`(30일 만료)이다. 만든 날을 `FIGMA_READ_TOKEN_SET_AT`에 적는다. 엔진 daily 작업이 하루 한 번 `--check`를 돌려서, 토큰이 거부되거나 만료 5일 전이면 맥 알림으로 재생성을 요청한다.

## 색

- 메인 컬러는 `#E56C4E`(테라코타)다. Figma 변수는 `color/brand`, 스타일은 `OOMAP/Brand`다. 칩, 닉네임처럼 포인트에만 쓴다. **장소 번호 원에는 색을 넣지 않는다**(흰 원 + `#111` 숫자 유지, 2026-11-04 사용자 결정).
- 배경은 `#252525`, 글자는 `#E4E4E4`·흰색이다.

## 0. 장수 한도

- 앱에서 직접 올릴 때: 최대 20장(2024-08부터). Template 2는 표지 + CTA 2장을 빼면 장소 최대 9곳(18장)이다.
- API(`media_publish`)로 올릴 때: 최대 10장. Template 2는 장소 최대 4곳(1 + 8 + 1)이다.
- 지금은 사람이 앱에서 게시하므로 20장 기준이다. 5곳 묶음은 12장이다.

## 1. 사진

- 직접 찍은 사진(`place_photos.source = 'own'`)만 쓴다.
- Cloudinary에서 받을 때는 변환 주소(`c_limit,w_1600`)로 받는다. 예전에 올린 사진은 회전 정보 태그만 붙어 있어서, 원본 주소로 받으면 누울 수 있다.
- **흐린 사진은 쓰지 않는다.**
  - 선명도는 가장자리 검출 값의 분산으로 잰다. 800px로 줄인 사진을 100px 칸으로 나누고, 상위 25% 칸의 평균을 쓴다.
  - 시험 제작 기준으로 600 미만이면 흐리다고 본다. 사용자가 흐리다고 한 사진은 292였다.
  - 지도 캡처처럼 글자가 많은 화면은 점수가 높게 나오니 따로 빼야 한다.
- **같은 장소 두 장은 다른 장면으로 고른다.** 예: 음료 1장 + 공간 1장. 연속으로 찍은 거의 같은 컷은 같이 쓰지 않는다.
- 4:5 카드에는 세로 사진을 먼저 고른다. 가로 사진은 양옆이 많이 잘린다.
- 보정은 가볍게 한다. 과하게 보정한 사진은 오히려 AI로 의심받는다.

## 2. 표지

- 카테고리 칩(일식·중식 등)은 넣지 않는다.
- 제목에는 지역과 구체적인 쓸모를 짧게 넣는다. 예: 「용산에서 오래 머물고 싶은 카페 5곳」.
- 표지는 릴스의 첫 3초와 같다. 넘겨 보게 만드는 사진을 쓴다.
- 제목은 **딱 2줄**로 쓰고, 줄바꿈(`\n`)을 직접 넣는다. 280px이면 한 줄에 9자 정도가 들어간다. 두 줄 길이를 비슷하게 맞춘다(짧은 줄 너비 ÷ 긴 줄 너비 ≥ 0.7, 각 줄 2651px 이하). Figma에서 줄마다 너비를 재서 확인한다.
  - 나쁜 예: 「용산에서 오래 머물고 싶은 / 카페 5곳」 (13자 / 4자)
  - 좋은 예: 「오래 머물고 싶은 / 용산 카페 5곳」 (너비 1932 / 1587)
- 제목은 280px(`font/size/cover-title`)로 쓴다. 위치는 x 291이고, 아래 끝을 3389에 맞춘다. 제목 줄 수가 달라져도 아래 끝은 그대로다.

## 2-0. 닉네임

- 닉네임 컴포넌트(854×170)는 모든 장(CTA 제외)에서 가로 가운데, y 180에 둔다. 표지도 같다.

## 2-0-1. 장소 소개 장

- 사진 위에 「하단 그라데이션」을 깐다. 검정 기준으로 위 45%는 투명이고, 65% 지점 45%, 82% 지점 75%, 맨 아래 88%로 어두워진다. 아래쪽 흰 글자(번호·이름·주소·소개)가 사진 밝기와 상관없이 읽히게 하려는 것이다.

## 2-1. 툴팁

- 툴팁 자리는 카드마다 사진을 보고 정한다. 모든 카드에 같은 자리를 쓰지 않는다.
- `admin/scripts/card-tooltip-place.py`로 자리를 찾는다. 사진에서 복잡도(가장자리 세기 + 질감)가 가장 낮은 곳을 고른다. 사진 가운데는 피사체가 있을 가능성이 높아서 점수를 더 나쁘게 친다.
- 툴팁은 본문 여백(295px) 안쪽에만 둔다. 카드 끝에 붙이면 화면 가장자리나 손가락에 가려진다(2026-11-04 사용자 지적).
- 세로 범위는 닉네임 아래(520)부터 장소 소개 글 아래 끝(3554)까지다. 그보다 아래는 인스타 하단 UI에 가린다. 닉네임(1193,180,854,170) 주변 60px은 비운다(`--avoid 1193,180,854,170`).
- 툴팁은 카드 바로 아래 레이어로 둔다. 「단순 글」 그룹 안에 두면 좌표가 그룹 기준이 되어 위치가 어긋난다.

## 3. 캡션

**참고 계정 @bbang.morning(빵모닝)·@yllo_selection 캡션 구조를 그대로 따른다** (2026-11-04 사용자 지시. 임의 형식 금지).

```
(⭐️저장) [질문형 또는 궁금증을 부르는 한 줄]

[왜 모았는지 2줄]. [공유 유도 한 줄 — "~한 친구한테 공유해두자"]

❶ [가게 이름]
[한 줄 설명]
📍 [전체 도로명 주소]

❷ ...

더 다양한 [주제]가 궁금하다면?

[바라는 것]하고 싶은 사람에게
― 지금 바로 @chyubeleub_j 팔로우해두자!

#해시태그 5개 (지역+카테고리)
```

- 번호는 ❶❷❸, 주소는 📍 + 전체 도로명 주소. 동네 이름 괄호 대신 주소를 쓴다.
- 설명은 장소마다 한두 문장. 길게 풀지 않는다.
- 마무리 팔로우 문구는 매번 같은 틀(yllo 방식). 무엇을 계속 받는지 말한다.
- 말투는 운영자 말투(반말 ~다, ~자나..?, 넘 좋다). 해요체·정리체는 쓰지 않는다.
- 내용은 공개된 추천 이유(`recommendations`)에서만 가져온다.
- 원문은 옮기지 않는다. 구조만 빌린다. 참고 원문은 business_discovery로 다시 볼 수 있다.

## 4. CTA 장

- 지금 CTA 문구는 팔로우·저장 유도다. 여기에 **DM 공유 유도**를 더한다.
- 이유: 비팔로워 도달에는 DM 공유가 가장 크게 작용한다(모세리 발언으로 확인됨).
- CTA는 로컬 폰트(Pretendard)로 되어 있어서 클라우드에서 글자를 못 고친다. 문구는 사용자가 Figma에서 직접 바꾼다.

## 5. 성과 측정

- 게시 후 Insights는 수가 아니라 **도달 대비 비율**로 기록한다.
  - 공유율 = shares / reach
  - 저장률 = saved / reach
  - 좋아요율 = likes / reach
- 다음 기획에서는 공유율과 저장률이 높았던 주제와 지역을 먼저 고른다.
- **기준값:** 2025-02 이후 게시물 23개(2026-11-04 조회).

  | 지표 | 범위 |
  |---|---|
  | 공유율 | 대부분 0~0.9% (0인 게 많음) |
  | 저장률 | 0~1% |
  | 좋아요율 | 2~9% |

  2024년 이전 게시물은 좋아요가 도달보다 많게 나와서, 도달 집계를 믿을 수 없다. 기준에서 뺀다.
